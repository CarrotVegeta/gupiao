# 外部「竞价选股」规则核验

2026-09-18。逐条核对外部给的这套竞价规则，用项目已有的 140 个交易日历史。

**结论：规则 1 的核心论断被数据否定；规则 2/3 需要的 09:25 竞价量能没有可用的历史来源，
现在无法回测，因此现在也不能按这套规则训练概率模型。**
替代做法是把两条规则直接做成**硬门槛**（不需要拟合任何权重，见第五节），
同时把线上每天都在算的 09:25 竞价量能按交易日落盘，攒够样本后再回头校准阈值。

复现：

```bash
npx tsx scripts/auction-gap-rule-check.ts     # 规则 1 逐档核对
npx tsx scripts/auction-volume-pilot.ts       # 规则 2/3 的量能代理预实验
```

## 一、规则 1（竞价涨幅分档）：被数据否定

### 原文断言 vs 实测

样本：2026-02-27 ~ 09-16，140 个交易日，11,596 条候选（可买到 10,747 条）。

| 原文断言 | 实测 | 判定 |
| --- | --- | --- |
| 2.8~3.5% 当日收红概率 **87.2%** | **71.5%** | ✗ 高估 15.7 个百分点 |
| <2.8% 日内翻绿概率 **超 60%** | 整体 **53.7%**；只有「低开」那一段 66.1% | △ 方向对，数字只对低开成立 |
| >7% 是「主力出货高发区」，全部规避 | >7% 是**封板率最高**的一档（可买到 45.7%，2.8~3.5% 只有 21.6%） | ✗ 理由不成立 |
| 3.5~7% 必须配巨量量能，否则极易高开低走 | 3.5~7% 可买到：收盘价 > 开盘价 49.5%（各档里最高） | ✗ |

### 收红概率随竞价涨幅单调上升，没有「黄金区间」

| 竞价涨幅 | 样本 | 收盘 > 昨收（收红） | 收盘 > 开盘 | 收盘涨停 | 次日开盘卖 |
| --- | ---: | ---: | ---: | ---: | ---: |
| <0% | 3,669 | 33.9% | 47.9% | 4.2% | -0.41% |
| 0~2.8% | 4,376 | 56.5% | 47.6% | 11.9% | -0.22% |
| **2.8~3.5%** | **589** | **71.5%** | 47.7% | 21.6% | -0.45% |
| 3.5~5% | 1,078 | 77.4% | 44.5% | 35.7% | -0.31% |
| 5~7% | 792 | 81.2% | 39.4% | 44.3% | -0.52% |
| 7~9% | 316 | 86.4% | 52.2% | 44.3% | -1.33% |
| ≥9% | 776 | 88.9% | 16.2% | 70.0% | +1.03% |

2.8~3.5% 不是峰值，只是这条单调曲线上的一个普通点，而且比它右边每一档都低。
用「主板涨停幅度」归一化之后结论一样（0.28~0.35 收红 72.8%，0.35~0.7 收红 76.2%，≥0.7 收红 88.4%）。

### 「>7% 规避」这条结论对，但原因是价格不是出货

只看**可买到**的那部分（竞价没封板）：

| 竞价涨幅 | 样本 | 收盘涨停 | 当日收盘卖 | 次日开盘卖 |
| --- | ---: | ---: | ---: | ---: |
| 2.8~3.5% | 589 | 21.6% | — | -0.45% |
| 3.5~5% | 970 | 30.8% | — | -0.55% |
| 5~7% | 620 | 36.1% | — | -0.89% |
| 7~9% | 307 | 43.6% | — | -1.24% |
| ≥9% | 216 | 48.6% | — | -0.74% |

高开越多，封板率越高（这条规则说反了），但**次日开盘卖出的收益越差**。
问题不在「主力出货」，在于**这份确定性已经写进开盘价里了**——你付出的溢价正好吃掉超额收益。
所以「别追太高」是对的，但依据应该是「买入价」，不是「出货」。

> 这与 `docs/auction-winrate-study.md` 第五节独立得到的结论一致：
> 在线上「较高概率」池里，`竞价涨幅≤7%` 不提高封板率，但把次日开盘收益从 -0.80% 提到 +0.19%
> （差 +1.69pp，bootstrap 95% 区间 [+0.37, +2.91]）。

## 二、规则 2/3（量能、竞价换手率）：现在无法回测

### 历史 09:25 竞价量能，把能试的都试了

| 来源 | 结果 |
| --- | --- |
| 腾讯分笔 `action=data&c=sh600519&p=0&d=<日期>` | `d` 参数被忽略，永远返回当日 |
| 腾讯分笔 `action=download&c=sh600519&d=<日期>` | 返回「暂无数据」 |
| 腾讯分时 `minute/query?code=...&date=<日期>` | 日期被忽略，`"date"` 永远是今天 |
| 同花顺分时 `d.10jqka.com.cn/v6/time/hs_600519/<日期>.js` | 日期被忽略，返回今天 |
| 东财 `push2his` 分钟K线（含 `beg`/`end`） | 连接直接失败（http=000），与 README 记录一致 |
| 东财 `push2delay` 分钟K线 | `rc:102`，不支持 |
| 网易 `quotes.money.163.com/cjmx/.../<日期>.xls` | 502，上游不可达 |
| 新浪 `CN_Bill.DetailList?date=` | `Service not found` |
| **新浪分钟K线 `scale=5/15/30/60&datalen=1023`** | **可用**，但只有 1023 根（scale=15 约 62 天、scale=30 约 124 天） |
| 腾讯分钟K线 `mkline` | 固定 320 根，与请求数量无关（m5 约 7 天、m15 约 20 天、m30 约 40 天、m60 约 77 天） |

**新浪分钟K线是唯一可用的免费源**，但批量抓 3031 只时触发了新浪的爬虫限流
（`你的 IP 存在异常访问...`）。这次只抓到 96 只就停了（覆盖 000010~000158，全部深市主板，
434 个候选日）。限流只影响离线抓取；线上行情走腾讯，不受影响。
后续要补数据必须把并发压到极低、拉长时间，或者用商业接口。

### 用「首根分钟K线量」当代理，预实验

集合竞价那一笔会并入当日第一根分钟K线，所以
`量比代理 = 首根K线量 / 近5日同一根均量`。但**第一根K线同时包含开盘后的连续竞价**，
所以它对「首根内就摸到涨停」的票有同时性污染。

| 代理 | 分组 | 样本 | 封板率 | 当日收红 | 次日开盘 |
| --- | --- | ---: | ---: | ---: | ---: |
| 15分钟首根 | 量比 <3 | 94 | 16.0% | 43.6% | -0.04% |
| | 量比 3~5 | 28 | 17.9% | 39.3% | -1.79% |
| | **量比 ≥5** | **23** | **47.8%** | 65.2% | +3.20% |
| 15分钟首根 · **剔除首根内封板** | 量比 <3 | 81 | 4.9% | 34.6% | -1.06% |
| | 量比 3~5 | 22 | 4.5% | 27.3% | -3.17% |
| | 量比 ≥5 | 16 | 31.3% | 50.0% | +2.46% |
| 15分钟首根 · **改用第二根（不含竞价）** | 量比 <3 | 113 | 23.0% | 49.6% | +0.22% |
| | 量比 ≥5 | 9 | 22.2% | 22.2% | -0.23% |
| 30分钟首根 | 量比 <3 | 226 | 18.6% | 50.0% | +0.12% |
| | **量比 ≥5** | **45** | **44.4%** | 73.3% | +2.90% |
| 30分钟首根 · **剔除首根内封板** | 量比 <3 | 186 | 6.5% | 39.8% | -1.11% |
| | 量比 ≥5 | 28 | 14.3% | 57.1% | +0.23% |
| 30分钟首根 · **改用第二根（不含竞价）** | 量比 <3 | 264 | 22.3% | 53.0% | +0.30% |
| | 量比 ≥5 | 23 | 30.4% | 65.2% | +1.71% |

怎么读这张表：

1. **表面效果很大**：量比 ≥5 那一档，封板率是低量比档的 2~3 倍。
2. **但一半是同时性**：剔除「首根K线内就摸到涨停」的样本后，15 分钟代理从 47.8% 掉到 31.3%，
   30 分钟代理从 44.4% 掉到 14.3%。第一根K线量之所以大，有一部分就是因为那根K线里它在封板。
3. **换一个不含竞价的窗口就基本消失**：用第二根K线算量比，15 分钟代理完全没区分度（23.0% vs 22.2%），
   30 分钟代理还剩一点（22.3% vs 30.4%，n=23）。
4. **两个代理彼此高度一致**（分位相关 0.944），说明代理本身稳定；不稳定的是它与结果的关系。

**所以：量能有没有增量信息，这份数据回答不了。** 样本只有 96 只、434 个候选日，
而且窗口越靠近开盘越受同时性污染。「量比 ≥5」这个具体阈值、「成交额 ≥800/1500/3000 万」、
「竞价换手率 ≥0.8%/0.5%」、「竞昨比 ≥3%」——全部没有被验证，也没有被否定。

还有一个量纲问题：用 15 分钟首根算出来的「竞昨比」**100% 都超过 3%**
（15/240 = 6.25% 是均匀分布下的下限），而真正的竞价占比通常在 0.1%~2%。
也就是说这条规则的阈值必须用**真竞价成交额**才能检验，代理的尺度差了 15~30 倍。

## 三、因此不能按这套规则重新**训练概率模型**（但可以先上硬门槛）

「重新生成模型」需要：把规则里的因子做成特征 → 在历史样本上拟合 → 走前验证 → 写回
`server/auction/model-parameters.ts`。这套流程项目里是现成的
（`scripts/auction-segmented-model.ts --write`），但前提是**特征在历史每一天都能重建**。

- 规则 1（竞价涨幅）能重建，但它的核心论断被数据否定，做成硬门槛会**降低**封板率。
- 规则 2/3（量比、成交额、换手率、竞昨比）**无法重建**，所以无法拟合，也无法验证。

强行用首根分钟K线代理去拟合，会把「同时性污染」写进权重——那是拿结果解释结果，
上线后必然比回测差。这一步不做。

## 四、已经做了什么：把 09:25 竞价量能存下来

线上一直接回了这些数，只是从来没存：

- `auctionAmount`（09:25 集合竞价成交额）
- `auctionRatio`（竞价成交额 / 昨日全天成交额）
- `previousAmount`（昨日全天成交额）
- `floatMarketCap`（流通市值，除以竞价价就是流通股本）
- `auctionPrice` / `auctionPct`

新增 `server/auction/snapshot-log.ts`，在 `/api/auction` 返回成功快照时
顺手把上面这些字段按交易日写一行 JSONL（同一交易日只写一次，写失败不影响接口）。

- 默认路径 `data/auction-snapshots.jsonl`，可用 `AUCTION_SNAPSHOT_FILE` 覆盖；
  生产环境的工作目录是发布目录（`deploy-remote.sh` 会整体替换），
  长期保存必须把这个变量指到发布目录之外。
- 标签（当日是否封板、次日开盘收益）事后用日K补算，不在落盘时猜。

有了它，规则 2/3 里每一个因子都能用**真实的 09:25 成交额**重建。
按 80~90 只候选/天算，攒 40~60 个交易日就有 3,000~5,000 条样本、400~700 个正例，
足够做一次走前验证。

## 五、已落地：竞价判定换成两条件硬门槛（2026-09-18）

按「只要达到这两个条件就判定为合格，其他的都不合格」重做了线上判定，
**不再计算封板概率**：

| 条件 | 阈值 | 位置 |
| --- | --- | --- |
| 竞价高开幅度 | `2% ≤ 涨幅 ≤ 6%` | `src/lib/auction-policy.ts` |
| 竞价量比 | `竞价成交额 ÷ 昨日全天成交额 ≥ 5%` | 同上（≥10% 额外标「爆量」） |

- 结果只有三档：`合格 / 不合格 / 数据不足`（拿不到竞价成交额就算不出量比）。
- 排序：合格在前 → 昨日连板数降序 → 竞价量比降序 → 代码。
- 页面把两个条件拆成两列，各自带 ✓/✗，不再显示概率。
- 概率模型（`server/auction/model.ts`、`model-parameters.ts`）保留给离线研究，
  线上路径不再调用；顺带去掉了炸板家数和大盘缺口两个已经用不到的上游请求。
- 阈值**仍未验证**：09:25 竞价量能没有免费历史接口。`data/auction-snapshots.jsonl`
  从今天开始每天落一条，攒够 40~60 个交易日后再用真实竞价成交额回测这两个阈值。

实测（2026-09-18 盘中，47 只候选）：合格 8 只、不合格 39 只、数据不足 0 只。

## 六、还可以做的

   （见 `docs/auction-winrate-study.md` 第五节：次日开盘 -0.80% → +0.19%）。
2. **等数据**。攒够之后用真实竞价成交额重跑 `scripts/auction-volume-pilot.ts` 的同款分析，

## 局限

- 规则核验用的是项目自建的涨停历史（新浪日K重建），不是官方逐日快照。
- 量能预实验只有 96 只深市主板股票、434 个候选日，且集中在 000010~000158，存在板块偏。
- 首根分钟K线代理与真竞价成交额的尺度差 15~30 倍，不能直接套规则的绝对阈值。
- 9 月 18 日的数据未参与任何拟合或阈值选择。
