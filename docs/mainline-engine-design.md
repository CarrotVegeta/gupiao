# 第一部分 · 主线判定规范

## 1. 判定总纲

> **主线 = 资金反复做的方向；支线 = 资金偶尔轮动的方向。**

四个判定层次，串联，缺任一层都会误判：

| 层 | 回答 | 排除 |
| --- | --- | --- |
| **L1 板块层** | 今天热的是哪些板块，是不是**反复**热 | 「今天涨幅第一」这类单日假象 |
| **L2 题材层** | 这个板块里资金**具体在炒哪条逻辑** | 宽概念凑数 |
| **L3 阵容层** | 资金结构完不完整（龙头/中军/补涨） | 个股行情冒充板块行情 |
| **L4 时间层** | **分歧之后钱还回不回来** | 一日游消息刺激 |

L1 不过 → 不进候选；L2 提不出题材 → 降级为「宽概念」；L3 阵容残缺 → 降为支线；L4 分歧不回流 → 判退潮。

## 2. L1 · 板块层候选

### 2.1 排序指标

原方法：在「行情 → 板块 → 概念板块」里分别按 **涨幅 / 涨停家数 / 主力净流入 / 成交额** 排序。

**只用同花顺时的调整**（原因见 §10.3）：主力净流入进入候选池需要逐板块请求，见 §11.2 的取舍说明。

| 榜 | 指标 | 同花顺字段 | 可得性 |
| --- | --- | --- | --- |
| ① PET | 板块涨幅 | `realhead.199112` / `block_top.change` | ✅ |
| ② LMT | 涨停家数 | `block_top.limit_up_num`（上游直接给） | ✅ |
| ③ FLW | 主力净流入 | `realhead.527198` | ⚠️ 逐板块请求 |
| ④ AMT | 成交额 | `realhead.19` / 板块日K 第 7 列 | ✅ |

### 2.2 候选与「反复出现」

```
TopN = 10

候选 Cand(d) = { b : 四个榜任一 Rank ≤ TopN }

Hit(b,d)       = |{ 榜 : Rank_榜(b,d) ≤ TopN }|        // 当日 0~4
StreakHit(b,d) = 连续多少个交易日 Hit ≥ 2               // 按交易日历
Repeat(b,d)    = StreakHit(b,d) ≥ 3                     // 「反复出现」
```

用「多榜同时持续」而非「单榜持续」，是为排除口径假象。

**原方法原话保留**：不要只看涨幅第一，重点记录连续 3 天反复出现的题材；每天从涨幅前 10 中筛出「涨停多 ＋ 成交放大 ＋ 连续出现」的 2~3 个方向。

## 3. L2 · 从板块里找题材

### 3.1 原方法的定位

> 有些看似独立的题材，其实是主线内部的分支。例如主线是「人工智能」：算力、服务器可能是主分支；液冷、光模块可能是轮动分支；某个临时 AI 应用概念可能只是支线。
> **判断方法是看它和总主线是否同步**：总主线上涨它跟着涨；总主线分歧它独立走强；总主线回流资金又优先回到它。**能够多次独立加强的分支，可能晋升为新的主线。**

### 3.2 题材提取（六步）

```
① 锚定集合   A_b(d) = { s ∈ members(b) : 涨停(s,d) }     // 只有涨停股有涨停原因
② 标签展开   reasonTags(s)（reason_type 按 + 、 / 拆）
③ 通用词过滤 剔除业绩/增长/定增/回购/控制权变更/次新股…（表见 §7.2）
④ 同义归一   半导体存储/存储芯片 → 存储；芯片扩产/产能扩张 → 芯片扩产（表见 §7.3）
⑤ 计家数     cnt(tag) = 带该标签的涨停股数（同一票同一标签只算一次）
⑥ 成题门槛   cnt ≥ 2

T_b(d) = { tag : cnt ≥ 2 }，排序：家数 → 最高板 → 首封时间
```

### 3.3 题材的三层验证

```
① 板块内成立   cnt(tag,b,d) ≥ 2
② 全市场对照   outOfBoardRatio = (marketCnt − cnt) / marketCnt
③ 跨板块扩散   同一 tag 出现在多个板块的 T_b(d) → 主线扩散证据
```

### 3.4 主分支 / 轮动分支 / 独立题材

```
branchOverlap(b1,b2) = |members(b1) ∩ members(b2)| / min(|…|,|…|)
sync(b1,b2)          = corr(P(b1), P(b2), 20 日)

主分支    overlap ≥ 0.5 且 sync ≥ 0.6
轮动分支  0.2 ≤ overlap < 0.5 且 sync ≥ 0.4
独立题材  overlap < 0.2 或 sync < 0.2

独立加强：在总主线 M 的下跌日（P(M,d) < 0），若 P(b,d) > 0 且 L(b,d) ≥ 2
独立加强次数 ≥ 2 → 潜在新主线
```

## 4. L3 · 阵容层（五档梯队）

### 4.1 五档定义（原方法）

| 位置 | 代表意义 | 判定特征 |
| --- | --- | --- |
| **高度龙头** | 3 板、4 板以上，打开市场空间 | 板块内最高连板 ≥3 |
| **前排核心** | 2 板或强势反包，提供板块强度 | 2~3 板家数 ≥2 |
| **中军** | 大市值、大成交额，稳定板块容量 | 见 §4.3 |
| **首板助攻** | 涨停数量持续增加，资金扩散 | 首板家数及环比 |
| **低位补涨** | 主线内部不断挖掘新分支 | 新增首板且此前未在该板块涨停 |

### 4.2 完整梯队模板（原方法原话）

> 「**5 板龙头 ＋ 2 只 2 板 ＋ 6 只首板 ＋ 大成交中军**」→ 主线特征比较明显
> 「**只有一只龙头涨停，其他股票冲高回落，更像个股行情，不算板块主线**」

### 4.3 中军判定（防做假）

```
中军 s ∈ core(b,d):
    成交额 ≥ 5 亿  且  流通市值 ≥ 100 亿  且  涨幅 > 0

coreSupport = min(1, |core|/3)
            × (中军成交额之和 / 板块成交额)
            × (中军主力净流入 > 0 的比例)
```

没有「流通市值 ≥ 100 亿」这条，「中军」会退化成「今天成交额最大的票」。

## 5. L4 · 时间层

### 5.1 连续计数（关键：分歧日不断链）

原方法只给了「连续 2~3 天保持强势」，未定义分歧日。规范补上：

```
P > 0 且 L ≥ 2                                    → C += 1        (强势日)
−3% ≤ P ≤ 0 且 L ≤ max(1, 0.3·L_prev)             → C 不变        (分歧日，不断链)
P < −3%  或  (L = 0 且 P < 0)                     → C = 0         (断链)
```

**分歧日归零会把真主线误杀**——主线不会每天涨，缩量小幅调整是必要环节。

### 5.2 分歧后回流（原方法称「最重要的指标」）

原方法：

> **主线**：加速上涨 → 分歧调整 → 资金回流 → 再次上涨
> **支线**：消息刺激 → 集体冲高 → 炸板回落 → 后面无人接力
> **不要因为板块调整一天就否定主线**，要看调整时核心股有没有承接，以及次日资金会不会回流。

操作化：

```
分歧日 d0（三条件同时成立）:
    ① −3% ≤ P(b,d0) ≤ 0
    ② L(b,d0) ≤ max(1, 0.3·L(b,d0−1))
    ③ 主力净流入(b,d0) ≥ 0

回流确认（窗口 w = 2 日）:
    存在 d1 ∈ (d0, d0+w]:  ④ P ≥ +1%  且  ⑤ (净流入 > 0  或  L ≥ 0.6·L(b,d0−1))

R(b,d) = +1  前 3 日内出现过被确认回流的 d0
       =  0  出现过 d0 但未确认
       = −1  d0 后第 2 日仍 P < −2% 且 L 继续下降（退潮）
```

### 5.3 主 / 支对照（原方法）

| 维度 | 主线 | 支线 |
| --- | --- | --- |
| 持续时间 | 数天甚至数周 | 多为 1~3 天轮动 |
| 涨停梯队 | 龙头、中位股、首板齐全 | 通常只有少数个股 |
| 板块容量 | 能容纳大量资金 | 容量较小 |
| 成交额 | 持续位于市场前列 | 偶尔放量 |
| 市场地位 | 大盘强弱围绕它变化 | 受主线或消息影响 |
| **分歧表现** | **分歧后经常回流** | **分歧后容易直接结束** |
| 催化逻辑 | 政策、产业趋势或长期事件 | 临时消息、事件刺激 |
| 个股扩散 | 龙头→中军→补涨不断扩散 | 龙头涨，后排跟不动 |

## 6. 主线评分表

**逐条保留原方法**：

| 条件 | 分数 |
| --- | ---: |
| 涨停家数进入前三 | +2 |
| 有市场最高连板或核心龙头 | +2 |
| 有大成交趋势中军 | +2 |
| 板块成交额进入前五 | +2 |
| 连续 3 天保持活跃 | +2 |
| 分歧后出现回流 | +2 |
| 有持续政策或产业催化 | +1 |
| 出现完整涨停梯队 | +2 |
| 大量冲高回落或炸板 | −2 |
| 龙头断板后全板块退潮 | −3 |

**判断标准**：**10 分以上**市场主线 / **7~9** 主线候选或次主线 / **4~6** 支线题材 / **3 分以下**一日游概率较高。

> **原方法声明**：分数不是机械买卖信号，主要用于**防止被当天涨幅迷惑**。

### 6.1 五个核心条件的并行切面

| 核心条件 | 内容 | 对应评分项 |
| --- | --- | --- |
| ① 有足够强的逻辑 | 政策 / 产业周期反转 / 产品涨价 / 技术突破 / 订单持续落地 / 空间足够大；只有一条突发新闻很难成主线 | 持续催化 +1 |
| ② 有完整的核心阵容 | 情绪龙头 ＋ 趋势中军 ＋ 弹性核心 ＋ 低位补涨 | 完整梯队 +2、中军 +2、最高连板 +2 |
| ③ 有持续的成交量 | 连续多日位于市场前列 / 逐步放大 / 放量时资金优先进入 / 缩量时仍有承接 | 成交额前五 +2 |
| ④ 有持续的涨停梯队 | 高度龙头 ＋ 2 板前排 ＋ 首板助攻 ＋ 趋势中军；**只有高位龙头、首板越来越少 = 退潮阶段** | 完整梯队 +2、连续 3 天活跃 +2 |
| ⑤ 分歧后能够回流 | 加速 → 分歧 → 回流 → 再涨 | 分歧回流 +2 |

> **只有一只股票强，不叫主线；一批股票形成联动，才叫题材主线。**

## 7. 支线判定与操作

### 7.1 支线特征（满足多数即支线）

```
涨停数量只有 2~4 只        没有明确的高度龙头
没有大成交中军             由一条临时消息刺激
板块成交额较小             龙头涨、后排不跟
经常趁主线分歧时上涨        主线回流后，支线马上回落
```

### 7.4 支线操作（原方法：支线不代表不能买）

```
适合做：消息刚出现时的前排 / 支线辨识度最高的龙头
       与主线逻辑有关联的分支 / 主线高位后的低位切换
最忌讳：买后排跟风股
```

## 8. 收盘后固定工作流（原方法）

```
① 概念板块分别按 涨幅 / 涨停家数 / 主力净流入 / 成交额 排序
   记录连续 3 天反复出现的板块（不要只看涨幅第一）
② 涨停聚焦／涨停分析：看题材有没有完整梯队
③ 从板块里找题材，区分主分支 / 轮动分支 / 支线（看同步性）
④ 收盘打分（§6）
⑤ 次日验证：分歧日核心股有没有承接，次日资金会不会回流（§5.2）
```

**连续性样例（原方法）**：

```
第1天涨停10只 → 第2天分歧、龙头继续晋级 → 第3天中军放量、低位补涨 → 第4天调整后又回流
    → 更像主线
第1天涨停15只 → 第2天只剩1只涨停、大部分低开低走
    → 一次性消息题材
```

```

| --- | --- |

# 第三部分 · 面板设计

## 13. 设计原则

原方法是**一套收盘后的固定动作序列**（§8），面板必须照着这个序列设计，而不是做成「一个排行榜 + 一个详情页」。

四条原则：

1. **照抄动作序列**：面板的信息层级 = 方法的步骤顺序（排序 → 反复出现 → 梯队 → 题材 → 打分 → 验证）
2. **口径必须可见**：同花顺口径 vs 自算口径、涨停家数的定义、Top20 限制——全部显式标注，不藏
3. **缺失就留白**：算不出来的字段显示「不可用 + 原因」，不用别的数字顶（项目既有原则）
4. **分数要能拆**：每个评分项显示「命中/未命中 + 依据数字」，不是只给一个总分

# 第四部分 · 验收

## 18. 判定方法必须接受检验

### 18.1 回测设计

| 项 | 设定 |
| --- | --- |
| 区间 | **受 `block_top` 历史深度限制**，先实测可回溯多久（§11.2） |
| 收益口径 | T+1 开盘买 / T+1 收盘卖；T+5；用等权成分股（板块指数不可交易） |
| 基准 | 全市场等权；「涨停家数前三」朴素口径 |
| 分层 | 按 §6 分档（≥10 / 7~9 / 4~6 / ≤3） |
| 消融 | 逐项去掉评分条件，看还有没有区分度 |
| 必查 | 前视偏差：所有输入只用 d 日收盘及之前 |

### 18.2 必须提前接受的三个可能结论

1. **主线池本身可能没有超额**。项目已有归因（`README.md:401-413`）：主线池 T+10 仅 +0.084%；叠「均线多头」反而 −2.4%（t=−2.25）。
2. **改善可能全部来自「排除」而不是「选出」**。那产品形态是「别买什么」。
3. **可能只有「分歧后回流」这一项有效**，其余是噪声。若如此就砍到只剩 R + 闸门，别硬留好看的评分表。

### 18.3 验收线

- 市场主线档 T+1 开盘→收盘超额 > 0 且 **t > 2**
- 相对「涨停家数前三」朴素口径有**可测量**改善
- `R = +1` 与 `R = −1` 样本收益差显著
- 消融实验能指出**至少两项是噪声**

**四条都过不了 → 本文判定方法只作「读懂资金在做什么」的仪表盘，不接任何选股结论。**

### 18.4 首轮回测结果（2026-08-10 ~ 2026-09-18，30 个交易日）

**实测结果：一条验收线都没过。**

```text
T+1 日内收益（次日开盘买 → 次日收盘卖，成员等权）
  基准           样本   均值      超额        t值    胜率
  全市场近似        29    -0.50%     0.00%    -2.24  27.59%
  涨停家数前三       87    -0.66%    -0.16%    -3.16  31.03%

  分档              样本   均值      超额        t值    胜率
  市场主线(≥10)       3    -1.29%    -0.79%    -1.50   0.00%
  候选(7~9)          37    -0.79%    -0.29%    -2.63  29.73%
  支线(4~6)         204    -0.59%    -0.09%    -3.99  36.27%
  一日游(≤3)        336    -0.32%    +0.18%    -2.39  41.67%
```

**读出来的三件事**：

1. **分数越高，次日越差，而且是单调的**（−1.29% → −0.79% → −0.59% → −0.32%）。
   方向是反的：评分表选出来的是**共识最强、当天最拥挤**的板块，次日开盘已经把情绪计入价格。
   这与原方法自己的声明一致——「分数不是机械买卖信号」。
2. **「涨停家数前三」朴素口径也没有超额**（−0.66%，超额 −0.16%，t=−3.16），
   说明问题不在评分权重怎么调，而在**这个方向本身在 T+1 日内没有可交易的钱**。
3. 全市场近似的胜率只有 27.6%、均值 −0.50%：**次日开盘买、收盘卖，本身就是负期望的操作方式**
   （涨停股次日高开后回落是结构性现象）。这说明**收益口径选错了**，
   不该用 T+1 日内，要用「次日开盘 → 后一日」，或者干脆测 T+5。

**当前结论（诚实版）**：这笔证据**不足以证明这套方法无效**，也不足以证明有效——
`市场主线` 只有 **3 个样本**，区间只有 30 个交易日，且历史上的资金流字段缺失
（`capitalReturn` 与 `coreTroop` 两项不可判定，回测跑的是**降级版评分表**）。

**下一轮要改的三处**：

| 问题 | 改法 |
| --- | --- |
| 收益口径本身是负期望 | 换成「T+1 开盘 → T+5 收盘」，以及「T+1 开盘 → T+2 收盘」 |
| 样本太少、区间太短 | 区间拉到 2025-09-03 起全量（约 250 个交易日），`MAINLINE_BACKTEST_DAYS=250` |
| 资金流缺历史 → 两项不可判定 | 从今天起按日落 `realhead` 资金流快照（沿用 `data/auction-snapshots.jsonl` 的做法），攒够样本后重跑 |

**在改完这三处之前，本方法不接任何选股结论，只作仪表盘。**

1. **同义表被通用词表抢先否决**：「产能扩张」含通用词「扩产」，先判通用词就会丢掉它，
   于是归一表里的「芯片扩产」永远聚不起来。**必须同义表优先于通用词**。
2. **`coreAvailable` 的语义**：不是「全部成员都有数据」，而是「中军这一项能不能判定」。
   只要有一只票有成交额与流通市值就能判定；全都没有才叫不可判定。
   否则 block_top 的历史数据（不给成员成交额）会让所有板块都判成「没有中军」。
3. **板块掉出 Top 20 的日子被整段丢掉**：实测发现「连续 3 天」被算成断链，
   事实只是那天没进前 20。**必须按全序列给每一天补空行**，空行在连续性里判 weak（正确断链）、
   在排名里名次为 null（不计数）。
4. **`marketMaxBoard` 不能用 block_top 算**：那只是 Top 20 板块内的最高板，不是市场最高板。
   要用全市场涨停池（`fetchLimitUpPool`）。
5. **中军的证据文案要分三种**：可判定且有 / 可判定但没有 / 不可判定。
   写成一句话会在历史回填里输出「没有中军」这种错误结论。
