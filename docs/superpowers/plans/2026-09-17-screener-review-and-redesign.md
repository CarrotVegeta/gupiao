## 1. 结论与范围

**当前趋势和题材判定都有需要修改的地方。最重要的三个问题是：角色筛选池不符合用户希望的标签形式；判定口径与名称、原始方法存在偏差；数据缺失和代理指标被包装成了过于确定的结论。**

建议保留选股中的“趋势、题材”两个入口。进入一个题材后，展示同一份去重的股票列表，在股票旁标明“龙头、核心、趋势中军、潜在低位补涨”。不再让用户进入四个角色分类查看各自一批股票。

本文件依据：

- 当前会话全部需求与更正。
- 已直接读取的“趋势股筛选方法”会话，共三轮：趋势股方法、题材股方法、主线与支线条件。
- 当前前后端代码和既有回测脚本、设计文档。

审查方式：静态代码审查。本轮未重新运行回测、未验证实时上游数据、未做浏览器视觉验收。这里评估的是软件规则与需求的一致性，不证明某种交易方法能带来收益。

## 2. 已确认需求与未确认建议

### 2.1 用户明确要求

1. 本轮只分析、给出修改计划和文档，不直接修改业务代码。
2. 题材内部要能看出谁是龙头、谁是核心、谁是趋势中军、谁可能是低位补涨。
3. 这些身份是股票的标签，不是四个独立分类页。
4. 不希望每个分类下都出现多只同样被叫作龙头、核心的股票而无法辨别代表。
5. 结合原始选股想法审查趋势和题材规则，而不是只调整外观。

### 2.2 本文件提出、尚未作为既定需求的建议

- 龙头、核心、中军每个题材各优先标一只代表，允许空缺；潜在低位补涨暂建议最多两只。具体数量可在实施前调整。
- 同一只股票可以兼任多个角色，列表只显示一行。
- 证据不足时显示“龙头候选／待确认”，不为了凑齐角色强行贴标签。
- 主线、支线保留为题材分类；增加“待确认”状态和独立的阶段字段。
- 原聊天里助手给出的70分、75分、具体权重、成交额与涨幅阈值，属于方案来源，不是用户已确认的要求，也不是经过验证的最优参数。
- 旧设计文档中记录了过去的取舍，包括中军不强制均线多头、趋势范围不自动套用中军限制。不得在此次优化时悄悄反向修改，需通过独立规则版本表达。

## 3. 目标界面

### 3.1 页面组织

选股 → 趋势 / 题材。

题材页：上方显示日期、数据状态、主线／支线与待确认筛选；桌面端左侧题材列表，右侧显示选中题材。窄屏可继续采用列表进入详情的方式。

题材详情依次展示：题材名称与分类依据 → 近期变化摘要 → 同一张股票表 → 点击股票展开判断详情。

| 股票 | 角色标签 | 涨跌幅 | 成交额 | 关键依据 | 数据状态 |
| --- | --- | --- | --- | --- | --- |
| 示例A | 龙头候选、核心 | 示例值 | 示例值 | 板块内领先，带动性待验证 | 部分待验证 |
| 示例B | 趋势中军 | 示例值 | 示例值 | 相对成交容量、趋势结构 | 数据完整 |
| 示例C | 潜在低位补涨 | 示例值 | 示例值 | 同细分逻辑、相对低位、启动迹象 | 候选 |
| 示例D | — | 示例值 | 示例值 | 暂无明确角色 | 数据完整 |

以上为布局示意，不对应真实股票。

### 3.2 展示要求

- 删除题材详情的四个角色页签；可提供“只看有标签”的快捷过滤，但不恢复四个独立结果池。
- 标签只表示该题材内的身份；同一股票在另一题材内可以有不同标签。
- 核心标签旁说明当前使用的是“换手核心”判定，避免“核心”含义不清。
- 默认将有标签的股票排前，其他已扫描成员可查看；不要将未贴标签等同于差股或已排除。
- 显示候选成员数、已计算数、失败数和未扫描数，缺少覆盖时只能说“已扫描范围内的代表候选”。
- 点击标签可查：使用哪些条件、同题材比较位置、为何选它、哪些证据缺失。
- 题材总览上的龙头和详情中的龙头必须来自同一次角色判定，避免两处指向不同股票。
- 风险单独显示；风险查询失败写“未核验”，不能写“无风险”。
- 切换题材后保留列表滚动位置；返回或切换趋势入口后保留已应用条件。

### 4.1 趋势条件建议分层

1. 股票范围：市场、ST、题材范围；不同模板各自记录，不擅自把中军限制套到趋势扫描。
2. 趋势结构：均线排列、均线斜率、站稳比例。
3. 位置：MA5有向距离、10日及20日涨幅、距阶段高点。
4. 量价：缩量、上涨与下跌日量能关系、放量突破。
5. 观察状态：回踩MA5、首次回踩MA10、平台突破、加速。这些描述状态，不直接输出“买入”。

建议保留“原五条件”作为可复现模板。完整聊天方法作为另一候选模板，先确定口径再上线；不把两个版本的结果或回测混在一起。

### 5.1 建议的新分类方式

- **分类字段**：主线、支线、待确认。待确认是证据状态，不是另一种交易策略。
- **阶段字段**：初现、加强、分歧、回流、退潮、待判断。需要历史数据支持；第一版可以先只显示家数和强度变化，避免强行自动命名。
- **主线资格草案**：可用历史覆盖至少3个交易日、当日家数达到配置门槛、满足明确的持续活跃要求，再结合梯队和容量证据。连续≥2家还是连续≥5家必须明确记录，不能混用。
- **支线资格草案**：存在板块效应但尚未达到已定义主线要求，且数据足以做这一判断。数据缺失则待确认。
- **去重观察**：多个重叠概念可能由同一批涨停股推动，界面提示成员重叠，不把它们当成独立的多条主线证据。

### 5.2 本轮题材驱动与静态概念归属分开（新增，P0）

用户补充：某只股票虽然属于某板块，但本轮上涨未必在走该题材。**静态归属不能直接作为当日题材驱动的确认依据。**

当前按涨停股的F10纯正归属分组，同一只股票可以给多个概念贡献涨停家数。业务归属真实也不代表当天这些题材均在驱动它。由此可能虚增主线强度，并把实际走另一逻辑的股票选为龙头、核心、中军或补涨。

建议分别记录三类信息：

| 信息 | 含义 | 用途 |
| --- | --- | --- |
| 静态归属 | 公司业务、产品和概念标签 | 背景说明、发现候选，不直接确认当日驱动 |
| 本轮驱动 | 本次行情对应的事件或细分逻辑及其证据 | 决定题材活跃统计和角色评选资格 |
| 走势联动 | 与题材启动、加强、分歧的同步情况 | 辅助比较，不单独证明驱动原因 |

每个“股票×题材×观察日期/本轮行情”记录关联状态：

- **驱动有依据**：有对应日期的公告、事件、相关涨停原因等可追溯证据；表示证据支持，不宣称已证明价格变化的唯一原因。
- **可能相关**：业务相关并有响应迹象，但证据不足或有冲突。
- **仅概念归属**：只查到静态归属，没有本轮驱动依据。
- **存在其他驱动**：当前证据更支持另一逻辑，显示替代解释；不自动否认可能同时存在其他驱动。
- 获取证据失败时另标数据缺失，不能自动视为“仅概念归属”或“不相关”。

统计和标签要求：

1. 区分“概念成员涨停数”“驱动有依据涨停数”“待确认关联涨停数”。主线判定优先使用有驱动依据的口径；证据覆盖不足时输出待确认，不能假装真实家数为零。
2. 龙头、核心、中军、补涨先经过本轮关联检查再比较。仅概念归属的股票可保留在表中，但不能据此获得确定角色标签。
3. 低位补涨必须核查与龙头的本轮细分逻辑，不能只因共享宽泛概念就判补涨。
4. 保留多重驱动，不强制每只股票只归一个题材；跨题材汇总按股票去重，展示重叠贡献，不能将各题材家数直接相加当作独立市场广度。
5. 保存来源、发布时间、获取时间、依据摘要、有效观察区间和规则版本。旧公告、通用关键词或单纯走势同步不能独立确认新一轮驱动。
6. 涨停原因、新闻文本也可能概括不全或有冲突。保留来源差异，无法自动判断时待确认；可后续支持有理由、有时间记录的人工更正。
7. 历史分类只能使用当时可获得的证据。当前归因不能反写为历史已知事实；统计口径改变后，旧阈值与旧回测需重新核验适用性。

界面在统一股票表中增加“本轮关联”列或说明，详情展示证据、其他可能驱动和联动指标。这是角色标签的前置步骤，不新增四个角色分类页。

## 6. 角色判定：从多个结果池改成少量标签

### 6.1 当前确定存在的问题

1. **所谓硬条件并非全部必须满足。** `ROLE_MIN_HITS` 为龙头4、核心4、中军6、补涨4；实际按命中数过滤。某项关键条件失败仍可能入选。页面“满足硬条件”的描述不准确。
2. **缺少唯一代表选择。** 判定后按命中数、成交额排序，每类最多返回60只，天然会出现多个“龙头”。
3. **龙头有两套答案。** 题材总览按最高板和首封选一个，详情按另一套命中计数输出多只。
4. **候选范围偏窄。** 龙头、换手核心只从当日涨停股中选，非涨停日的核心会被排除；不能把“当日未涨停”直接当作角色消失。
5. **带动性只是代理。** 首封之后又有股票涨停，不能证明由它带动；首末封时间变化也不能直接证明分时承接。
6. **补涨启动时差实际上无法确认。** `leaderFirstSealDate` 在编排层始终为null，2～4天条件无法命中，但补涨仍可凭其他4项入选。
7. **突破日期只识别最新一天。** `findBreakout` 不是找历史最近突破；因此启动前后持续跟踪与字段“最近突破日期”的含义不一致。
8. **启动间隔按自然日。** 应改为交易日；龙头启动锚点应对应本轮题材，而不是任意最近20日的最早涨停。
9. **未涨停成员关联证据不足。** 当前上下文主要补齐当天涨停股的F10信息，普通成员可能缺关联依据和原因标签，不能直接视为“不纯正”。
10. **风险在初筛排序后才查询。** 查询后没有统一重筛排序；风险未知或风险命中仍可能保留。并且详情表未直接渲染独立的risks字段，其他角色不一定能看到风险。
11. **并列排名处理不明确。** 同高度和同启动日期按数组顺序得到不同名次。应使用明确的并列排名，再用有依据的次级条件比较。

### 6.2 建议判定流程

统一题材成员 → 对齐数据时间 → 核查本轮题材驱动 → 计算公共指标 → 分角色检查必要资格 → 同题材比较 → 选择代表或保留待确认 → 输出每只股票的标签数组。

**必要资格不能被其他分数抵消。** 风险、题材关联、关键数据是否充足要独立处理。角色比较分只在符合必要资格的候选中使用，不显示成上涨概率。

| 标签 | 主要比较依据 | 避免的误判 |
| --- | --- | --- |
| 龙头 | 本轮启动位置、持续领先、相对强度、可获得的板块响应证据 | 最高板或最早首封直接等于龙头 |
| 核心（换手核心） | 板块内成交地位、持续活跃、换手结构、抗跌性与承接证据 | 炸板次数多、成交额大直接等于核心 |
| 趋势中军 | 相对成交容量、趋势持续性、与题材联动、调整稳定性 | 任意满足均线条件的股票都叫中军 |
| 潜在低位补涨 | 同细分逻辑、相对涨幅位置、实际启动迹象、本轮时序、题材阶段 | 涨得少或价格低就算补涨 |

没有分钟级响应数据时，龙头标签默认带“候选”或证据说明。未知项不计作通过；也不等同于明确失败。数据覆盖不足时不宣称已经找到全题材最强者。

### 6.3 数量与稳定性建议

- 龙头、核心、中军各优先一个代表；潜在补涨暂建议最多两个。
- 允许标签空缺、兼任，不要求每个题材凑齐四种身份。
- 候选接近、数据不足时保留待确认；次级候选放在展开说明里，不在主表给一排同名确定标签。
- 分数轻微变化不立即频繁换标签；确认失效、重大风险或明显更强候选出现时重新评估，并记录变更依据。具体稳定窗口通过观察样本确定。
- 主线、支线共用一张表和标签机制。支线默认更集中展示龙头与核心；不要再创建独立角色页签，也不要强行指定补涨。

## 7. 数据一致性与错误状态

### 7.1 必须修正

- 历史日期请求中，行情、板块日K、个股日K未统一按请求日期截断；交易日历从最近日期获取。应使用目标日及之前的数据，缺历史快照则明确不支持精确历史重建。
- 当前F10归属用于历史涨停分组存在前视偏差。开始保存每日归属快照；没有历史快照时标“按当前归属回溯”。
- 部分历史涨停池失败未被完整传播，可能变成0家，错误打断持续性。必须区分“真0家”和“数据缺失”。
- 题材服务可能返回fresh并附带error，客户端题材解析却将fresh且error非空视为不可用。前后端需统一部分可用契约。
- 趋势与详情请求失败时保留同一查询条件下的上一轮结果并标过期；不同题材或参数的旧结果不得冒充当前结果。
- 日K按日期对齐，统一复权、成交量单位、成交额口径；此项是实施前待核验项，本轮未证明上游一定不一致。

### 7.2 板块跨源映射

当前用成员重叠寻找对应同花顺板块，并有名字模糊匹配兜底。它是匹配推断，不是保证一一对应。建议保存映射来源、重叠程度和匹配状态；不确定时缺省显示相关指标未知，避免把另一板块的量价拼接进当前题材。

## 8. 回测结论与界面文案需要修正

现有页面使用“已被回测否定”“毒源”等确定性表述。建议改为：

> 本项目既有样本中，原五条件组合的表现不支持收益优势。该研究存在历史归属和执行口径等限制，不代表所有趋势方法无效；当前页面用于形态与题材结构观察。

这不意味着旧研究没有价值，也不意味着应恢复均线多头为中军硬条件。需要限制结论的适用范围。

已检查到的研究限制：

1. 回测的主线定义为家数门槛加持续天数，线上为家数加8项命中数；两者不同。
2. 回测五条件并非原聊天完整趋势方法，未覆盖所有斜率、阶段位置和加速过滤。
3. 脚本用收盘信息判定，再按同一收盘价入场。这是理想化研究口径；模拟可执行交易时需改为下一可交易时点或明确假设。
4. 使用当前题材归属回溯历史，存在前视偏差。
5. 多日收益窗口重叠，现有t值使用普通均值/标准误计算；需考虑序列相关后再解释显著性。
6. 70%/30%按信号日期划分，需检查跨分界的持有期并设置隔离区；验证集反复用于挑规则后，也不能继续当作完全未见样本。
7. 成本、滑点、涨跌停无法成交和停牌等约束，应在可执行策略测试中显式建模；不能只在文案中提及。

后续若重新研究：线上和回测复用同一规则定义；保存规则版本、参数、样本期、数据来源和结果范围。新参数组合不能沿用旧模板的绩效结论。

## 10. 关键回归场景

| 场景 | 期望 |
| --- | --- |
| 题材有多个达标龙头候选 | 主表突出一个代表或显示待确认；其他候选进入依据详情 |
| 一只股票同时是龙头和核心 | 一行、两个标签 |
| 当日核心未涨停 | 不仅因未涨停就消失，按统一身份规则重新评估 |
| 风险接口失败 | 显示未核验，不显示无风险 |
| 龙头首板日期缺失 | 补涨时序未知，不能宣称已满足2～4交易日 |
| 周五启动、周一跟进 | 按交易日计算，不算3个交易日 |
| 一板、三板齐全但缺二板 | 不称完整的一二高梯队 |
| 历史一天接口失败 | 持续性未知，而非涨停0家 |
| 切换题材A到B，A较晚返回 | B页面不能被A结果覆盖 |
| 盘中成交量不及前日全天 | 不直接标记已确认缩量回调 |
| 全市场仅处理260只 | 明示部分覆盖，不能宣称全市场筛选完成 |
| 规则参数修改 | 旧回测不得作为新规则的验证结果 |
| 股票属于A、B概念，本轮证据仅支持A | A可计驱动有依据，B保留静态归属或待确认，不自动给B贡献已确认驱动家数 |
| 同一股票确有A、B双重驱动证据 | 允许两边关联，显示重叠；跨题材汇总只计一只 |
| 公告与涨停原因不一致或证据接口失败 | 显示冲突/缺失和待确认，不强行确定角色 |
| 补涨候选与龙头只有宽泛概念相同 | 不认定已满足同细分驱动条件 |
| 使用本轮最新证据查看历史日期 | 不把晚于观察日期的信息当作当时已知依据 |

实施阶段使用针对性Vitest测试、`npm run typecheck`及必要的页面验收。业务代码变更后再运行完整回归和构建；本次仅写文档，不宣称这些检查已通过。

## 11. 第一轮落地范围建议

第一轮优先交付：**本轮题材驱动核查、统一股票列表＋角色标签、关键判定纠错、数据状态与请求一致性**，即阶段1～3。先明确股票本轮是否在走该题材，再评选该题材内的角色代表。

趋势条件升级作为随后一轮；事件日历、复杂百分制评分、完整情绪周期识别与新回测不必阻塞标签界面的完成。

本轮不恢复四个角色分类页，不默认扩大自动交易功能，也不修改旧文档历史记录。后续正式实现时用新规则版本明确替代关系。
