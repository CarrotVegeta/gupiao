# 大盘行情、左侧导航与涨停聚焦设计

## 目标

在现有 A 股个人股票看板上增加统一的左侧一级导航和顶部大盘行情，并新增“涨停聚焦”页面。用户可以在“持仓”和“涨停聚焦”之间切换：持仓页面保留现有收益、备注、分组和股票管理；涨停聚焦页面展示最新交易日全部涨停股票、连板数和所属行业板块。

## 已确认的交互口径

- 一级导航固定在主内容左侧，只包含“持仓”和“涨停聚焦”。
- 大盘行情固定显示在主内容顶部，展示上证指数、深证成指、创业板指和科创 50。
- 持仓页面的分组导航位于股票列表上方，不再占用一级导航位置。
- 涨停聚焦包含数据源返回的全部股票，不排除 ST、风险警示或其他标的。
- “几板”使用涨停池返回的连续涨停板数字；“板块”使用数据源返回的行业板块名称。
- 涨停聚焦以接口返回的交易日期为准；非交易日没有股票时显示“暂无涨停数据”，不伪造交易日或股票。
- 行情和涨停数据只保存在运行时缓存，不写入现有 `localStorage` 持仓数据。

## 页面结构

页面采用桌面端两栏布局，小屏幕自动堆叠：

```text
┌────────────────┬─────────────────────────────────────┐
│ 一级导航       │ 大盘行情                              │
│                ├─────────────────────────────────────┤
│  持仓          │ 当前页面内容                          │
│  涨停聚焦      │                                       │
│                │                                       │
└────────────────┴─────────────────────────────────────┘
```

### 一级导航

新增 `PrimaryNav` 组件，负责：

- 展示“持仓”和“涨停聚焦”两个按钮；
- 通过 `aria-current` 表示当前页面；
- 显示持仓数量和当日涨停数量（若数据尚未加载则显示加载状态或 `—`）；
- 不承载分组筛选和分组增删操作。

### 顶部大盘行情

新增 `MarketOverview` 组件，固定位于主内容顶部：

- 上证指数、深证成指、创业板指、科创 50 四个行情项；
- 显示指数名称、最新点位、涨跌额和涨跌幅；
- 上涨使用暖红色，下跌使用青绿色，无数据使用中性灰色；
- 显示最近一次更新时间和刷新状态；
- 作为全局行情条，在两个一级页面中都可见。

### 持仓页面

保持现有总览和持仓管理能力，但调整顺序为：

1. 总收益率和收益汇总；
2. 分组导航（全部持仓、未分组、自定义分组、新建分组）；
3. 当前分组股票列表；
4. 添加股票入口保留在股票列表区域。

分组导航仍然通过 `selectedGroupId` 筛选持仓，并同步影响当前范围的收益汇总。分组删除、股票编辑和股票删除逻辑不改变。

### 涨停聚焦页面

新增 `LimitUpList` 组件：

- 页面标题为“涨停聚焦”；
- 显示接口返回的交易日期、涨停总数、最高连板数和数据状态；
- 使用表格展示全部结果，列为：股票、连板、涨停板块、最新价、涨跌幅、首次封板、最后封板、炸板次数；
- ST 和风险标的照常显示，不添加过滤开关；
- 数据为空时显示明确空状态；
- 数据刷新失败时保留上一轮数据，并显示“数据已过期”提示；
- 不显示持仓收益和分组导航。

## 数据模型

在 `src/types.ts` 增加运行时数据类型：

```ts
type MarketIndex = {
  symbol: string;
  name: string;
  price: number | null;
  change: number | null;
  pct: number | null;
  updatedAt: string | null;
  status: "fresh" | "stale" | "unavailable";
};

type MarketOverviewResponse = {
  indices: MarketIndex[];
  fetchedAt: string;
  source: "eastmoney";
  errors: Array<{ symbol: string; message: string }>;
};

type LimitUpItem = {
  symbol: string;
  name: string;
  price: number | null;
  pct: number | null;
  boardCount: number | null;
  firstSealTime: string | null;
  lastSealTime: string | null;
  industry: string | null;
  breakCount: number | null;
};

type LimitUpResponse = {
  tradeDate: string | null;
  items: LimitUpItem[];
  fetchedAt: string;
  source: "eastmoney";
  status: "fresh" | "stale" | "unavailable";
  error: string | null;
};
```

`LimitUpItem` 使用标准化后的 6 位代码，不能把原始 `QuoteID` 或市场前缀传给页面。缺失字段显示 `—`，不把缺失值当成 0。

## 服务端接口与数据源

### 大盘行情

新增：

```text
GET /api/market-overview
```

服务端通过东方财富指数列表接口请求四个指数：

- `1.000001`：上证指数；
- `0.399001`：深证成指；
- `0.399006`：创业板指；
- `1.000688`：科创 50。

适配器读取最新价、涨跌额、涨跌幅、指数代码和名称，并转换为 `MarketIndex`。任何单个指数失败都进入 `errors`，不影响其他指数；整批失败时返回上一轮缓存由前端保留。

### 涨停聚焦

新增：

```text
GET /api/limit-up?date=YYYYMMDD
```

`date` 可选，缺省使用 Asia/Shanghai 当前日期。服务端请求东方财富 `getTopicZTPool` 接口，使用：

- `c` 映射股票代码；
- `n` 映射名称；
- `p` 按千分位缩放为最新价；
- `zdp` 映射涨跌幅；
- `lbc` 映射连续涨停板数；
- `fbt`、`lbt` 转换为 `HH:mm:ss`；
- `hybk` 映射行业板块；
- `zbc` 映射炸板次数。

服务端按接口返回的总数继续请求分页，直到收齐全部 `pool` 结果或上游返回空页；不按名称或风险标记过滤。若上游返回空 `pool`，仍返回成功响应和对应 `tradeDate`，让页面显示当日没有涨停数据。

路由正常返回标准化 `LimitUpResponse`：上游有有效响应时 `status` 为 `fresh`，上游异常时 `status` 为 `unavailable` 并填写 `error`，HTTP 状态仍为 200，便于前端统一处理并决定是否保留上一轮数据。

### 请求与刷新

- 页面首次加载请求大盘行情；
- 页面可见时每 30 秒刷新大盘行情；
- 进入涨停聚焦或点击刷新时请求涨停数据；涨停聚焦处于可见页面时每 30 秒刷新；
- 请求失败保留上一轮成功数据，并将状态标记为 `stale`；没有上一轮数据时标记为 `unavailable`；
- 服务端请求设置 5 秒超时，并把上游错误转换为稳定的中文提示。

## 前端代码边界

- `src/types.ts`：新增大盘和涨停聚焦共享类型；
- `src/lib/market.ts`：大盘接口请求、响应校验、展示格式化；
- `src/lib/limitUp.ts`：涨停接口请求、响应校验和状态合并；
- `src/components/PrimaryNav.tsx`：持仓/涨停聚焦一级导航；
- `src/components/MarketOverview.tsx`：顶部指数行情条；
- `src/components/LimitUpList.tsx`：涨停聚焦摘要和表格；
- `src/App.tsx`：一级页面状态、全局大盘刷新、页面内容切换；
- `src/components/GroupSidebar.tsx`：调整为持仓页面的分组导航，并放置在股票列表上方；
- `src/styles.css`：两栏布局、顶部行情条、涨停表格和小屏幕响应式样式；
- `server/quotes/eastmoney.ts`：指数和涨停池字段适配；
- `server/index.ts`：新增 `/api/market-overview` 和 `/api/limit-up` 路由。

现有持仓、搜索、收益计算和 `localStorage` 代码保持职责不变，不为新页面引入第三方 UI 框架或数据库。

## 错误处理与安全边界

- `date` 只接受 8 位数字日期，非法日期返回 400；
- 服务端对上游结果做字段校验，丢弃代码或名称缺失的坏行；
- 真实涨停价格、板块和连板数仅展示数据源返回值，不在前端推断；
- 上游失败不会清空大盘或涨停上一轮数据；
- 数据源不可用时页面仍可切换、查看和管理本地持仓；
- 继续保留“个人记录工具，不构成投资建议”的产品说明。

## 测试策略

1. 东方财富适配器单元测试：指数字段缩放、涨停字段映射、时间转换、空池、分页合并、坏数据过滤和上游失败。
2. 前端请求单元测试：请求参数、响应校验、刷新失败后的 stale 保留和空数据处理。
3. 组件交互测试：一级导航切换、顶部行情显示、分组导航位于股票列表上方、涨停表格列和错误状态。
4. App 集成测试：进入涨停聚焦时请求涨停数据，切回持仓后原分组和收益数据保持不变。
5. 继续执行现有 `npm run typecheck`、`npm test` 和 `npm run build`。

## 验收标准

- 页面左侧清晰显示“持仓”和“涨停聚焦”两个一级入口；
- 页面顶部同时显示四个大盘指数及涨跌数据；
- 持仓页面中分组导航位于股票列表上方，切换分组仍能更新股票列表和总收益率；
- 涨停聚焦展示接口返回的全部股票，包含 ST 和风险标的；
- 涨停股票至少能看到代码、名称、连板数、行业板块、涨跌幅和封板信息；
- 非交易日或空数据时有明确提示；
- 上游失败时保留已知数据，且不影响持仓管理；
- 全量测试、类型检查、生产构建通过。
