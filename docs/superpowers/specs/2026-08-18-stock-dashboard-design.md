# A 股个人股票看板设计

## 目标

构建一个面向个人使用的 A 股股票看板：用户可以添加股票、按自定义分组管理，查看实时行情和当日涨跌幅，记录备注与开仓价，并根据持仓数量计算单只股票和全部持仓的收益率。

第一版优先解决“打开就能用”的个人场景，不引入登录、云端账户或数据库。股票和持仓信息保存到当前浏览器的 `localStorage`；行情由服务端代理公开 A 股行情接口，避免浏览器跨域和把行情供应商细节耦合到页面。

## 范围与成功标准

### 第一版包含

- A 股代码添加、编辑、删除
- 股票名称由行情接口返回；添加时允许用户只输入代码
- 自定义分组创建、重命名、删除和筛选
- 每只股票记录分组、开仓价、持有数量和备注
- 显示最新价、当日涨跌额、当日涨跌幅、行情更新时间
- 根据开仓价和最新价显示单只持仓收益额与收益率
- 顶部显示当前筛选范围内的总投入、总市值、总收益额、总收益率
- 行情手动刷新与交易时段内的定时刷新
- 行情请求失败时保留上一次成功数据，并在界面显示数据状态
- 空状态、表单校验和小屏幕布局

### 第一版不包含

- 登录、注册、跨设备同步
- 买入/卖出流水、手续费、分红、复权成本
- 港股、美股、基金和期货
- 价格提醒、自动交易和投资建议
- 历史收益曲线

## 产品与交互设计

### 页面结构

页面采用单页仪表盘布局，视觉重点放在持仓表现，而不是表格密度：

1. 顶部导航：产品名“自选台”、行情状态、最后刷新时间、刷新按钮和“添加股票”按钮。
2. 总览区：总收益率作为主指标，旁边显示总收益额、总投入、当前市值和持仓数量。
3. 左侧分组栏：全部持仓以及用户创建的分组；显示每组股票数量；提供新增、编辑、删除分组入口。
4. 主内容区：当前分组的股票卡片/表格。桌面端使用宽卡片布局，小屏幕自动改为纵向卡片。
5. 股票条目：股票代码与名称、当日涨跌、最新价、开仓价、持仓收益、备注和编辑/删除操作。

颜色使用语义化变量：上涨使用暖红色、下跌使用青绿色、未提供行情使用中性灰色。收益颜色只表达数值方向，不改变信息层级；所有数值同时显示正负号和百分比。

### 添加/编辑股票

表单字段：

- 股票代码：必填，接受 6 位数字，保存时去除空格
- 分组：必填，默认当前分组或“未分组”
- 开仓价：必填，必须大于 0，最多两位小数
- 持有数量：必填，必须大于 0，允许整数和两位小数
- 备注：可选，最多 120 个字符

用户提交后先保存本地持仓，再立即请求该股票行情；如果行情暂时失败，股票仍然保留，条目显示“等待行情”。编辑时保留原持仓记录的稳定 `id`。

### 分组

默认创建一个不可删除的“未分组”系统分组；“全部持仓”是只读的导航筛选，不是可分配给股票的真实分组。用户创建的分组名称必填且不能与已有分组重名。删除用户分组时，该组股票移动到“未分组”，不删除股票本身；系统分组不可删除。

## 数据模型与计算口径

### 本地数据

```ts
type StockGroup = {
  id: string;
  name: string;
  isSystem: boolean;
  createdAt: string;
};

type Holding = {
  id: string;
  symbol: string;
  name: string;
  groupId: string;
  openPrice: number;
  quantity: number;
  note: string;
  createdAt: string;
  updatedAt: string;
};
```

行情只存在于运行时缓存，不写入持仓实体：

```ts
type Quote = {
  symbol: string;
  name: string;
  price: number | null;
  change: number | null;
  pct: number | null;
  preClose: number | null;
  updatedAt: string | null;
  source: "eastmoney";
  status: "fresh" | "stale" | "unavailable";
};
```

### 计算规则

- 单只收益额：`(最新价 - 开仓价) × 持有数量`
- 单只收益率：`(最新价 - 开仓价) ÷ 开仓价 × 100%`
- 总投入：`Σ(开仓价 × 持有数量)`
- 当前市值：`Σ(最新价 × 持有数量)`，只计入有有效最新价的持仓
- 总收益额：`当前市值 - 总投入`，只有在所有持仓都有有效行情时才显示为确定值；否则显示“部分行情”状态
- 总收益率：`总收益额 ÷ 总投入 × 100%`
- 当日涨跌幅直接使用行情供应商返回的百分比，不用开仓价推算

金额按人民币显示，保留两位小数；收益率保留两位小数。没有有效行情时，收益相关字段显示 `—`，不伪造 0。

## 行情接口设计

### 服务端接口

```text
GET /api/quotes?symbols=600519,000001,300750
```

返回：

```ts
type QuotesResponse = {
  quotes: Quote[];
  fetchedAt: string;
  source: "eastmoney";
  errors: Array<{ symbol: string; message: string }>;
};
```

服务端验证并去重股票代码，单次最多请求 50 个代码。每个代码转换为东方财富接口需要的市场标识：沪市代码前缀 `1`，深市/创业板/科创板以外的 A 股代码按 `0` 处理。行情供应商适配器集中在 `server/quotes/eastmoney.ts`，页面只依赖标准化后的 `Quote`，未来更换数据源时不改变 React 组件。

第一版读取东方财富公开实时行情端点 `https://push2.eastmoney.com/api/qt/stock/get`，使用 `f43/f57/f58/f60/f169/f170/f86` 等字段映射最新价、代码、名称、昨收、涨跌额、涨跌幅和更新时间。上游字段解析失败、网络超时或返回空数据时，对应股票返回 `unavailable`，不会让整个批次失败。

前端刷新策略：首次加载后立即请求；用户点击刷新时立即请求；页面可见且有持仓时每 30 秒刷新一次。请求进行中禁用刷新按钮并展示加载状态；成功时更新缓存，失败时保留旧缓存并把旧数据标记为 `stale`。

## 代码边界

- `src/types.ts`：共享数据模型和派生结果类型
- `src/lib/calculations.ts`：纯计算函数，只处理收益和汇总，不依赖 React 或浏览器
- `src/lib/storage.ts`：`localStorage` 序列化、迁移和默认分组
- `src/lib/quotes.ts`：前端行情请求、错误转换和刷新状态
- `src/components/Overview.tsx`：总览指标
- `src/components/GroupSidebar.tsx`：分组导航与分组操作
- `src/components/HoldingList.tsx`：持仓列表、行情与收益展示
- `src/components/HoldingForm.tsx`：添加/编辑持仓表单
- `src/components/GroupDialog.tsx`：新增/编辑分组
- `src/App.tsx`：组合状态、筛选、刷新和弹窗状态
- `src/styles.css`：页面视觉样式和响应式布局
- `server/index.ts`：HTTP 服务和 `/api/quotes` 路由
- `server/quotes/eastmoney.ts`：东方财富行情供应商适配器

组件只接收明确的 props；计算逻辑集中在纯函数中，避免在渲染层重复计算和出现总览/列表口径不一致。

## 错误处理

- 代码格式不正确：表单字段下方直接提示，不发起行情请求
- 行情响应不完整：只让对应条目进入“暂无行情”，其他条目正常显示
- 网络错误或上游限流：保留已知报价，顶部显示“行情更新失败，显示上次数据”
- `localStorage` 读取损坏：恢复默认分组和空持仓，并显示一次非阻塞提示
- 删除分组：二次确认后移动股票到“未分组”，不丢失备注和开仓价
- 最新价缺失：不计算该条目的收益，也不把缺失值当作 0 参与总收益

## 测试策略

1. 纯函数单元测试：涨跌方向、单只收益、加权总收益、缺失行情、零/负数输入保护。
2. 存储单元测试：默认数据、保存读取、损坏 JSON 恢复、分组删除后的迁移。
3. 行情适配器测试：字段映射、百分比单位、异常响应和单只失败不影响其他代码。
4. React 交互测试：添加股票、编辑备注、切换分组、删除分组迁移、刷新状态和空状态。
5. 构建验证：TypeScript 类型检查、Vitest 全量测试和 Vite 生产构建。

## 验收标准

- 新用户打开页面能看到清晰的空状态和添加股票入口。
- 添加 `600519` 并输入开仓价、数量后，页面能显示股票名称、最新价、当日涨跌幅和持仓收益。
- 至少两只股票放在不同分组时，切换分组只影响列表和当前范围汇总，不会丢失数据。
- 修改备注和开仓价后刷新页面，数据仍然存在。
- 删除一个自定义分组后，股票自动进入“未分组”。
- 行情接口失败时页面仍可操作，旧行情不会被错误清零。
- 单元测试、交互测试和生产构建均通过。
