# 股票持仓看板

这是一个用于个人跟踪持仓、分组、成本和实时行情的本地 Web 应用。

它是个人记录工具，不是投资建议。

## 本地运行

先安装依赖：

```bash
npm install
```

启动本地开发环境：

```bash
npm run dev
```

然后打开：

```text
http://localhost:5174
```

## 常用校验命令

```bash
npm run typecheck
npm test
npm run build
```

## 本地烟雾测试

建议按下面流程做一次完整验证：

1. `npm run dev`
2. 打开 `http://localhost:5174`
3. 新增股票 `600519`，也可以输入“贵州茅台”并从搜索候选中选择
4. 开仓价和持有数量可以留空；留空时股票会作为观察项保存
5. 需要计算收益时，编辑股票补录开仓价 `160` 和数量 `100`
6. 确认页面显示服务器返回的行情，或者显示“暂无行情/不可用”的可见状态
7. 页面顶部确认“大盘概览”可见，且指数卡片显示涨跌额 / 涨跌幅
8. 点击“涨停聚焦”，确认涨停表格可见，并包含“连板”和“板块”列
9. 点击“竞价”，确认展示上一交易日涨停股、09:25 固定竞价结果、每只票的“涨停概率”、“合格 / 观察 / 不合格”标识和“溢价”分档
10. 确认竞价列表优先按昨日连板数、再按评分从高到低排列
11. 切回“持仓”，确认“持仓分组”、收益率和“添加股票”入口仍然可见
12. 刷新页面
13. 确认持仓和备注仍然保留
14. 停止开发进程

## 数据保存

- 持仓、分组和备注都会保存在浏览器的 `localStorage` 中
- 本地存储键名为 `stock-dashboard:v1`
- 清空浏览器站点数据会清除这些记录
- 如果本地数据损坏，应用会自动恢复为默认状态

## 行情说明

- 页面行情由本地服务端接口 `/api/quotes` 提供
- 股票搜索由本地服务端接口 `/api/stock-search` 提供
- 服务端会再去请求公开行情源，因此查询行情需要网络可用
- 如果公开行情源在非交易时间或服务窗口外不可用，页面可能显示上一轮行情、过期行情或不可用状态

### 行情源：腾讯优先，东财兜底

`push2.eastmoney.com` / `push2his.eastmoney.com` 在部分网络会被上游**直接断连**，
这正是「行情大片缺失」的根因：个股行情、批量行情、大盘指数原先全部走 push2，一挂就全挂。

同一台机器、同一时刻各打 8~15 次（`npx tsx scripts/_host-health.ts`，结果见 `scripts/output/host-health.json`）：

| 上游 | 成功率 | p50 | 说明 |
| --- | --- | --- | --- |
| 东财 `push2` 单只/批量行情、`push2his` 日K | **0% ~ 25%** | — | `UND_ERR_SOCKET` / `RemoteDisconnected` |
| 东财 `push2delay` 批量行情、分笔明细 | 100% | ~46ms | 与主站同秒的**实时**镜像，不是延时行情 |
| 东财 `push2ex` 涨停池/强势池 | 100% | ~51ms | |
| 东财 `datacenter` 龙虎榜、`searchapi` 搜索 | 100% | ~53ms | |
| 腾讯 `qt.gtimg.cn` 单只/批量行情 | 100% | ~50ms | 返回 **GBK**，须用 `TextDecoder('gbk')` 解码，否则股票名乱码 |
| 腾讯 `ifzq` 日K / `stock` 分笔 | 100% | ~60ms | |
| 腾讯 `smartbox` 搜索建议 | 100% | ~58ms | |

因此行情链路改成：**腾讯 `qt.gtimg.cn` 优先 → 东财 `push2delay`（镜像）兜底 → `push2` 最后**。

| 数据 | 主源 | 备用源 |
| --- | --- | --- |
| 个股行情 `/api/quotes` | 腾讯 `qt.gtimg.cn`（批量 50 只/次） | 东财 `push2delay` → `push2` |
| 大盘指数 `/api/market-overview` | 腾讯 `qt.gtimg.cn`（带 sh/sz 前缀，`000001` 才能区分上证指数与平安银行） | 东财 `push2delay` → `push2` |
| 观察板块判定 `/api/watch-check` | 腾讯 `qt.gtimg.cn` + `ifzq` 日K | — |
| 股票搜索 `/api/stock-search` | 东财 `searchapi`（15/15 正常，未改） | — |
| 涨停池 / 强势池 / 龙虎榜 | 东财 `push2ex` / `datacenter`（一直稳定，未改） | — |
| 竞价链路 `/api/auction` | 腾讯 `stock.gtimg` 分笔（竞价价 + 量能）+ 东财 `push2ex` 池 | 东财 `push2delay` → `push2` 明细；腾讯 `qt` 报价 / `ifzq` 交易日历 |

响应里的 `source` 字段标明实际用了谁：`tencent`（全腾讯）、`eastmoney+tencent`（部分票由东财补齐）、
`eastmoney`（腾讯整批失败、全部走东财）。**已由东财补上的票不会留在 `errors` 里**，
否则前端会把它标成过期行情。

## 竞价筛选说明

- 候选范围为上一交易日收盘仍在涨停池内的股票
- 今日数据固定使用 09:25 集合竞价价格，不使用盘中最新价替代
- **涨停概率**：09:25 时点就能算出的「今天收盘继续涨停」的概率（0~100%），由逻辑回归模型给出
  - 特征（全部来自 09:25 可得的公开信息，无需额外抓个股数据）：今日竞价溢价、昨日连板数、昨日是否一字板、昨日换手率、流通市值、昨日涨停家数、昨日炸板家数、大盘竞价缺口
  - 训练：2026-02-26 ~ 2026-09-16 共 140 个交易日、12100 个样本，按交易日走前验证（只用历史数据拟合）
  - 样本外表现：AUC 0.813、Brier 0.116；概率校准良好，详见下表
  - 档位：`≥55% 合格`、`30~55% 观察`、`<30% 不合格`，对应历史实际涨停率约 65% / 45% / 11%（全样本基准 18.8%）
- **溢价**是独立维度，取值 `低吸 / 温和 / 溢价偏高 / 追高`：竞价溢价越高，涨停概率越高，但按竞价价买入的平均收益越低。概率回答「会不会连板」，溢价回答「这个价买划不划算」
- 竞价量能（竞价成交额 / 昨日成交额）只作为参考项展示，不计入概率。成交额取自腾讯分笔的**真实成交金额**
  （东财口径要自己用「价 × 手数 × 100」估算）；09:25 单笔量能无法回测，所以它不进模型
- 特征缺失时按训练均值代入，并在页面上标出缺失项数量，避免一个字段缺失就把概率压到错误区间

### 为什么竞价买入没有优势（重要）

同一批票、同样持有过夜，只在「什么时候买」上不同，结果完全相反（2026-02-26 ~ 09-16，不含手续费）：

| 入场方式 | 样本 | 次日开盘卖出 | t | 胜率 |
| --- | --- | --- | --- | --- |
| 竞价买入（今日 09:25 开盘价） | 9794 | **-0.41%** | -2.5 | 44% |
| 打板买入（当日封板后按涨停价）· 换手板 | 11450 | **+1.16%** | 14.3 | 58% |
| 打板买入 · 一字板（基本买不到） | 710 | +6.27% | 27.9 | 86% |

原因是涨停股的**次日高开溢价**：这个溢价是「持有涨停过夜」的报酬，竞价买入等于在次日替卖方承担它。
所以不是选股的问题——在可执行的次日卖出口径下，任何选股子集都无法让竞价买入转正。

打板分档（只看买得到的换手板）：

| 分组 | 样本 | 次日开盘卖出 |
| --- | --- | --- |
| 首板 | 9571 | +1.05% |
| 2 板 | 1338 | +1.62% |
| 3 板 | 310 | +2.20% |
| ≥4 板 | 231 | +2.54% |

叠加 09:25 涨停概率模型后（候选池当天真的封板的那部分）：

| 分组 | 样本 | 次日开盘卖出 | t | 胜率 |
| --- | --- | --- | --- | --- |
| 换手板 · 概率<30% | 914 | +1.49% | 7.3 | 59% |
| 换手板 · 概率 30~55% | 416 | +1.92% | 6.2 | 67% |
| 换手板 · **概率≥55%** | 257 | **+2.78%** | 6.3 | 65% |

概率在打板口径上单调有效，且 2 月到 9 月**每个月都是正的**（+0.68% ~ +1.56%）。概率≥55% 的票平均 2.5 只/天。

由此得到这个页面的正确用法：

1. 09:25 用概率筛出「今天可能封板」的票（≥55% 进重点池）
2. 盘中这些票真的封板时，在涨停价买入
3. 次日开盘卖出

**必须知道的风险**：换手板只是「当天开过板、理论上能成交」的代理，真实成交率取决于封单量和排队顺序；
一字板那 +6.27% 正是买不到的高收益样本，不能计入可实现收益。上面所有数字均未扣手续费（双边约 0.1~0.2%）。

### 具体案例：合格档 + 竞价未封板 → 竞价买入

140 个交易日里有 772 次「合格」（概率≥55%），其中 **576 次在竞价就一字封板、根本买不到**，
真正可买的只有 196 次（覆盖 92 天）：

| 指标 | 数值 |
| --- | --- |
| 当日收盘涨停（封板） | **43.4%** |
| 当日盘中触及涨停 | 60.2% |
| 胜率（次日开盘价 > 买入价） | **44.9%** |
| 胜率（次日收盘价 > 买入价） | 45.4% |
| 平均收益（次日开盘卖，按笔 / 日等权） | **-1.56% / -0.73%**（t=-0.86） |
| 盘中最大浮盈 / 最大浮亏 均值 | +2.49% / -6.79% |

结果高度两极分化，而这正是亏钱的原因：

| 分组 | 占比 | 当日收盘卖 | 次日开盘卖 |
| --- | --- | --- | --- |
| 当天封住 | 43.4% | +2.59% | +5.77% |
| **没封住** | **56.6%** | **-5.49%** | **-7.17%** |

这批票的当日开盘价平均比昨收高 **+9.04%**——买入时就已经把「可能封板」的预期付掉了，
所以 43% 的封板率也补不回 57% 那部分的亏损。按月看也不稳定：4 月 +2.76%、5 月 -0.25%、
6 月 -2.47%、7 月 -2.13%、8 月 +0.58%、9 月 -3.35%。

**对照**：同样这 772 次「合格」，如果在竞价已经封板时也能买到，次日开盘卖出胜率 60.4%、平均 +1.51%（t=2.93）。
再次说明「合格」这个信号本身是有效的，被吃掉的是竞价买入这个入场价。

复现：`npx tsx scripts/qualified-buy-backtest.ts [概率阈值]`

### 模型还有提升空间吗

试过再加 5 个特征（近 10 日涨停次数、涨停簇跨度、昨日炸板率、大盘 5/20 日涨幅）、4 个非线性项
（竞价接近涨停、竞价≥7%、低开、竞价×连板）以及 3 个位置特征（20 日涨幅、距 60 日高点、昨日振幅），
走前验证 AUC 分别是 0.8071 / 0.8072 / 0.8113，都没有超过现有 8 特征模型的 0.8132：

```text
B 当前线上 8 特征          0.8132
C +涨停历史/情绪/大盘趋势   0.8071
D C + 非线性项             0.8072
E D + 位置特征             0.8113
```

结论：**09:25 这个时点的信息已经被现有特征吃满**，继续堆特征只会过拟合。要再提升应当换时点
（例如引入盘中封单量、开板次数等 09:25 之后才有的信息），而不是继续加日线衍生特征。

### 数据源与稳定性

`push2.eastmoney.com` / `push2his.eastmoney.com` 在部分网络下会被上游直接断连（`other side closed`），
而 `push2ex`、腾讯行情不受影响。因此所有关键数据都做了备用源：

| 数据 | 主源 | 备用源 |
| --- | --- | --- |
| 09:25 竞价明细（竞价价 + 量能） | 腾讯 `stock.gtimg.cn` 分笔 | 东财 push2 → **push2delay**（同一份数据的镜像） |
| 交易日历 | 腾讯指数日K | push2his 日K → 按日期回扫涨停池 |
| 大盘竞价缺口 | 腾讯 `qt.gtimg.cn`（上证今开/昨收） | push2 单只行情 |
| 竞价价（腾讯分笔拿不到时） | 东财 ulist | 腾讯 `qt.gtimg.cn` |

> 行情页（`/api/quotes`、`/api/market-overview`）的选源依据、实测数据与改造结论见上文
> [行情源：腾讯优先，东财兜底](#行情源腾讯优先东财兜底)。

- **竞价成交的时间戳不总是 09:25:00**：实测约三分之一个股戳在 09:25:01~09:25:59
  （例如 2026-09-17 的澳弘电子是 `09:25:01`）。09:25:00~09:29:59 之间不存在连续竞价成交，
  因此取这个窗口内的第一条作为竞价成交，而不是写死匹配 `09:25:00,`
- **按源熔断**：东财明细链上某个源连续失败到阈值后，本次请求不再碰它但继续用镜像；
  全部源都挂掉时直接跳过剩余个股，避免对 80~90 只票逐个空转重试
- 逐笔明细接口只在传输失败时重试（最多 3 次）；上游给出合法响应后不再重试，避免把「没有 09:25 成交」误判成故障
- 详情抓取并发从 8 降到 4，减少上游限流
- 效果：主源被断连时，一次竞价请求从 **25.5s / 量能 0 只 / 每只缺 1 个模型特征**，
  先变成 **3.1s / 量能 89 只**（加 push2delay 镜像），再变成 **2.3s / 量能 89 只**（腾讯分笔做主源）
- `/api/auction` 按交易日缓存 5 分钟：09:25 快照当天不变，缓存既保证同一时段反复刷新看到同一份判定，也避免一次刷新打 80~90 个上游请求
- 只缓存成功结果，失败结果留给下次请求重试

### 竞价分笔：主源已换成腾讯

`stock.gtimg.cn/data/index.php?appn=detail&action=data&c=sh600519&p=0` 返回当日分笔
（`序号/时间/价格/涨跌/成交量(手)/成交额(元)/方向`，70 条一页，`p=0` 就是开盘最早那一段）。
用它和东财 `push2delay` 明细逐只对比：**89 只里竞价首笔价格 0 错、量能最大相对误差 0.011%**
（东财是估算值，腾讯才是真实成交额，所以以腾讯为准）。

端到端跑完整条链路（同一候选池 89 只）：

| 链路 | 墙钟耗时 | 有竞价价 | 有量能 |
| --- | --- | --- | --- |
| 旧：东财明细优先（主源被断连时先重试再切镜像） | 3.5 ~ 6.2s | 89 | 89 |
| 旧：全部分笔走腾讯（`scripts/auction-source-compare.ts` 的对照实现） | 1.6 ~ 2.0s | 89 | 89 |
| **现：腾讯分笔主源 + 东财兜底**（实测 `/api/auction`） | **2.3s** | 89 | 89 |

实现上有两点值得记：

- **先取批量行情，再逐只取分笔**：行情里的**今开就等于 09:25 竞价成交价**（开盘价由集合竞价撮合产生），
  两个批量请求就能覆盖全部候选，分笔只用来补「竞价成交额」
- **护栏用「今开 > 0」而不是本机时钟**：09:25 之前今开是 0，而分笔这时还在吐**上一交易日**的数据。
  用数据自身判断「今日是否已开盘」，不依赖机器时区与时间是否准确；今开为 0 时直接退回东财明细链，
  那条链在 09:25 前会诚实地返回「缺少 09:25 竞价成交数据」

**腾讯分笔拿不到量能时**（例如北交所个股，两家分笔都返回空）仍返回竞价价，量能标记为缺失——
量能是展示项，不影响概率与档位；这也是为什么不再为它回头重试东财。

两家分笔都只覆盖**最近一个交易日**：东财 `details/get` 的 `date` 参数被上游忽略
（实测传 `date=20260910` 与不传返回完全相同的当日数据），所以按历史日期请求竞价时，
候选池是历史快照、而竞价价只能来自最近的交易时段——这个限制在换源前后一致。

## 「观察」板块

「自选」页就是观察列表：自己添加股票（支持分组），显示最新价 / 涨跌额 / 涨跌幅 / 换手，
备注会作为红色小标签显示在股票名称右边（设计稿 F 的 `.tag`）。开仓价和数量留空时，
股票只出现在自选、不进持仓。

「我的票」表头有 **全部 / 持仓** 两个范围档：全部是整份自选，持仓是已补录开仓价和数量的票。
两档都只过滤当前列表，不会跳页——顶部的「持仓」页照旧保留。分组筛选跟着当前范围计数。

> 「观察」档位已经从自选页去掉：自选本身就是观察列表，再放一个「观察」筛选属于重复；
> 现在「观察」只作为竞价结论的一档（`30~55%`）出现在竞价页和右侧竞价候选侧栏里。

> 这里曾经做过一版「当日买入判定」，已按要求下掉。相关研究结论保留如下，代码在 `scripts/`：

- 全市场 39.5 万样本、T+1/T+2/T+3 三个周期检验下来，**日K没有任何可靠的买入信号**：
  回调、缩量、回踩均线、平台整理这些「买点」条件全部落在 ±0.2% 以内、t 值小于 1
- 唯一有正期望的形态是「当天封板」（T+1 +1.27%，t=6.58），但那是打板口径，需要买在涨停价
- 能可靠识别的是**亏损形态**，最强的一条是「3 日内有涨停、今天没封住」：T+1 -0.51% → T+2 -0.89% → T+3 -1.36%（t=-3.1）
- 「埋伏分」（低动量+低换手+低波动+小市值+低价）的日截面排序单调性很好：前 10% 的 T+5 +0.84%、
  后 20% -1.52%，样本外一致，但绝对收益只有零点几个百分点

后端的判定引擎（`server/watch/check.ts`）和它的测试保留着，只是没有接进页面；
如果确认不要了可以一并删掉。

## 股票标识（头像 + 标签）

所有出现股票名的列表（自选、持仓、涨停池、冲刺涨停、竞价、龙虎榜、右侧竞价候选）
统一用设计稿 F 的标识：名称左边是首字头像方块（沪市 `6` 开头蓝色、深市/北交所绿色），
名称右边是红底红字的小标签（`.stock-tag`）。标签内容按列表取该行最该被看到的信息：

| 列表 | 标签内容 |
| --- | --- |
| 自选 / 持仓 | 备注（`note`）+ 涨停标识：有备注时备注是红色主标签、涨停退成蓝色副标签；没备注时涨停标识自己当红色主标签（首板写「涨停」，2 板以上写「N 连板」） |
| 涨停池 | 连板数，如 `3 连板`（和「连板」列同值） |
| 冲刺涨停 | 涨停次数，如 `2 次` |
| 竞价候选（表格 + 右侧侧栏） | 昨日连板数，如 `2 连板` |
| 龙虎榜 | 上榜原因前 8 个字，完整原因仍在「上榜原因」列 |

自选/持仓的涨停标识来自**当天涨停池**（`/api/limit-up` 的 `lbc` 连板数，见
`src/lib/limitUpInfo.ts`），所以只有「今天封在涨停价」的票才有这个标签；
池子不可用时返回空表、不会清掉已有标签。自选/持仓页进入时会拉一次池子，
之后复用同一份数据，不额外增加请求。

组件在 `src/components/StockIdentity.tsx`，样式是 `src/styles.css` 末尾的
`.stock-identity* / .stock-tag / .stock-tag--secondary`（放在末尾是为了稳定压过
各列表自己的字号规则）。

## 回测与验证脚本

`scripts/` 下的脚本用于训练和校验模型，不参与构建：

```text
scripts/limit-up-history.ts     用日K自建涨停历史（新浪，140 个交易日、全市场 5500 只）
scripts/auction-model.ts        训练/验证涨停概率模型，输出系数与校准表
scripts/limit-up-hold-analysis.ts 入场口径对比：竞价买入 vs 打板买入、成交可行性与稳定性
scripts/qualified-buy-backtest.ts   「合格 + 竞价未封板 → 竞价买入」的胜率回测
scripts/watch-signal-lab.ts        买强类条件的验证（42 万样本，结论：无效甚至反向）
scripts/watch-timing-lab.ts        择时类条件的验证（39 万样本 × T+1/T+2/T+3）
scripts/watch-rank-lab.ts          市值/价格/波动/动量分位检验 + 市场择时
scripts/watch-ambush-lab.ts        埋伏分构造与样本外验证（输出运行时参数）
scripts/auction-success-rate.ts 当日盘中统计：封板率 / 触板率 / 收益，按概率分组
scripts/auction-stability.ts    连续两次抓取，检查判定是否稳定
scripts/_host-health.ts         上游主机巡检：逐个数据源打点，统计成功率/延迟/错误类型
scripts/source-benchmark.ts     腾讯 vs 东财 同数据对比：交易日历/大盘缺口/批量行情/分笔
scripts/auction-source-compare.ts 竞价链路端到端对比：现状（东财优先）vs 腾讯优先
scripts/output/                 数据集、模型参数与原始响应缓存（已 gitignore）
```

行情「大片缺失」时先跑 `npx tsx scripts/_host-health.ts`：能直接看出是某一家整站挂了，
还是单个接口改了字段。2026-09-17 的结论是前者 —— `push2` / `push2his` 全军覆没，其余上游全绿，
据此把行情主源切到腾讯。

为什么自建涨停历史：东财涨停池接口只保留约 15 个交易日，样本量不足以训练概率模型。自建名单已在 2026-09-16 与官方涨停池逐只比对，89 只全部命中（另多 2 只）。

模型自检：`npx tsx scripts/auction-model.ts` 会打印走前验证的 AUC、Brier 和校准表。改动特征或阈值后应当重新跑一遍，不要只看样本内。

```bash
npx tsx scripts/auction-model.ts          # 训练 + 走前验证 + 输出校准表
npx tsx scripts/auction-success-rate.ts   # 当日盘中统计
npx tsx scripts/_host-health.ts           # 上游健康巡检（行情缺失时先跑这个）
npx tsx scripts/source-benchmark.ts 6 4   # 腾讯 vs 东财 逐接口对比
```
